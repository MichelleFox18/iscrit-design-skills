# Реализация MVP: состояние

## Реализовано

- Next.js App Router + TypeScript + Tailwind CSS; все пользовательские тексты на русском.
- Публичная главная в стиле референсов, матрица с поиском/фильтром/сравнением,
  отдельные карточки компетенций, треки и материалы.
- PostgreSQL 17 вместо предложенного ранее Supabase: локальный Docker,
  серверная password/session-авторизация и реальные RLS-политики.
- Три роли и синтетические локальные аккаунты.
- Семь этапов review, независимые ответы self/manager/final,
  скрытие черновика руководителя и запрет подмены самооценки.
- Предварительный и итоговый расчёты по заданию; подтверждение двумя сторонами.
- Исправление подтверждённого итога только с причиной и повторным согласованием.
- Цели 3/6 месяцев: максимум одна общая и одна трека, 2–4 действия,
  два подтверждения, материалы, прогресс, отметки и ссылки, комментарии, перенос срока.
- История с динамикой областей и итогового балла; снимок целей при завершении.
- Командный обзор без рейтинга; административные формы пользователей,
  назначений, циклов, дат review, версий методики и материалов.
- Избранное, внутренние материалы, транзакционный неизменяемый аудит,
  backup и отдельная проверка восстановления.

## Отличия от первоначального предложения

Нет зависимости от внешнего Supabase-проекта. Таблица `ratings` содержит
отдельные строки для каждого автора; RLS ограничивает строки с черновиками,
а не скрывает поля в браузере. Матрица и треки хранятся как валидируемый
JSON внутри неизменяемых версий `matrices`; начатый цикл ссылается на версию.
История результативных числовых оценок остаётся в БД, изменения — в аудит-триггерах.

Начальный seed не содержит ни одной выдуманной компетенции. Существующие
названия областей и треков — из задания. Реальные внешние ссылки в материалах
не выдаются за содержимое исходной таблицы.

## Проверки

- 9 тестов правил расчёта и последовательных переходов прошли.
- Production build и TypeScript прошли.
- 8 групп интеграционных проверок прошли в отдельной временной БД, включая
  первичную установку настоящего администратора без demo seed:
  RLS, авторизация всех ролей, чужие URL/API и Origin, скрытые черновики,
  полный review, аудит исправлений, две стороны согласования,
  ограничения целей, прогресс, история, неизменяемая версия матрицы,
  сохранение материалов, изоляция избранного и запрет удаления аудита.
- Backup восстановлен в отдельную БД; данные администратора,
  RLS-флаги и политика чтения оценок восстановлены; временная БД удалена.

- Браузерный сценарий прошёл: публичные страницы на 1440/768/390px,
  вход трёх ролей, запрет административных и командных URL дизайнеру,
  добавление/удаление избранного, видимость только назначенного сотрудника,
  административные формы и выход через мобильное меню. Ошибок JavaScript нет.

Полный аудит WCAG AA и production-размещение не выполнены.

## Что блокирует готовность по бизнес-методологии

Не получен XLSX. Нельзя подтвердить состав и тексты компетенций,
все формулы, округление, правила Н/П в минимуме 11, методику треков
и отдельные условия экспертного/управленческого подтверждения.
Структурные и сквозные тесты используют техническую методику только
во временной тестовой БД; она удаляется и не публикуется в рабочей базе.

До получения и проверки книги рабочий каталог и циклы оценки пустые.
Полный критерий готовности MVP по действующей матрице пока не выполнен.
