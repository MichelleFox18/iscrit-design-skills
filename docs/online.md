# Размещение сайта в интернете

Сайт уже реализован как серверное веб-приложение. Публикация среды Codex
сохраняет окружение разработки; адрес сайта выдаёт отдельный хостинг.
Из текущей среды нет подключённого аккаунта хостинга или средства публикации.
Публичная ссылка ещё не создана. Код пока находится в рабочей среде,
в исходный GitHub-репозиторий изменения автоматически не отправлялись.

Для продолжения через Render API в настройках облачной среды подготовлено
требование секрета `RENDER_API_KEY`, разрешённое только для HTTPS-запросов
к `api.render.com`. Создайте ключ в своём аккаунте Render и введите его
значение в защищённом поле среды. Сохранение требования не создаёт ключ
и не предоставляет доступ к аккаунту. Не присылайте ключ в чат.
После сохранения/применения настроек доступ проверяется командой
`python3 scripts/check-render.py`: это чтение аккаунта, без создания
платных ресурсов. Одного подключения аккаунта недостаточно для выбора тарифа;
стоимость сервиса и БД нужно согласовать перед их созданием.

## Простой вариант: Render

Render позволяет разместить веб-приложение и PostgreSQL в одном аккаунте.
Будет стандартный адрес вида `https://<имя-сервиса>.onrender.com`.
Это пример формата, а не существующая ссылка на данное приложение.
Собственный домен можно подключить позже. Стоимость и условия хранения
БД нужно выбрать в интерфейсе Render; бесплатный тариф не следует считать
постоянным хранилищем внутренних данных без проверки его условий.

1. Создать аккаунт на https://render.com/ и подключить GitHub.
2. Опубликовать подготовленный код в `MichelleFox18/iscrit-design-skills`.
   До этого шага сайт нельзя собрать из текущего состояния удалённого репозитория.
3. Создать PostgreSQL и веб-сервис из этого репозитория, выбрать Docker.
   Проверка готовности веб-сервиса: путь `/materials`, который обращается к БД.
4. В защищённых настройках веб-сервиса указать:

| Переменная | Что указать |
| --- | --- |
| `MIGRATION_DATABASE_URL` | Внутреннюю строку подключения созданной БД с правами установки |
| `APP_DATABASE_PASSWORD` | Постоянный случайный пароль отдельной роли приложения |
| `INITIAL_ADMIN_EMAIL` | Почту первого администратора |
| `INITIAL_ADMIN_PASSWORD` | Новый пароль администратора, минимум 16 символов |
| `SEED_DEMO` | `false` |

Значения секретов вводятся в хостинге, не в чате и не в репозитории.
На Render канонический HTTPS-адрес читается из `RENDER_EXTERNAL_URL`;
для другого хостинга нужен `APP_ORIGIN`. Docker стартует через
`scripts/hosted-start.mjs`, создаёт схему/роль/первого администратора,
вычисляет runtime `DATABASE_URL` для `design_app`, удаляет миграционные
реквизиты из окружения процесса Next.js и слушает порт `PORT`.
Администратор не перезаписывается при повторном запуске. Demo seed выключен.

Перед выбором БД необходимо проверить, позволяет ли установочный пользователь
создать непривилегированную роль `design_app` и выдать ей доступ. Совместимость
с выбранным managed PostgreSQL не подтверждена без реального подключения.
Если это запрещено, роль создаётся средствами провайдера отдельно, схема
устанавливается одноразовым заданием, а веб-сервис запускается только с
`DATABASE_URL` и `APP_ORIGIN`, без миграционного bootstrap.

После запуска проверить внешним браузером главную, материалы, авторизацию,
cookie Secure, RLS, приватность карточек и сохранение после перезапуска.
Установить резервное копирование по возможностям выбранного хостинга.
Облачное размещение ещё не выполнено и не проверено.

Локально проверены Docker-сборка и hosted запуск на чистой временной БД:
установка схемы, создание настоящего администратора, публичные страницы,
вход, cookie Secure/HttpOnly, запуск без root и отсутствие `.env.local`
в образе. Команда проверки — `npm run test:hosted` после сборки образа
`iscrit-design-web:local`. Проверка удаляет свою временную БД и контейнер.
Для Docker-сборки внутри этой облачной среды потребовались поддерживаемые
proxy-настройки, разрешение имени proxy и доверенный CA через временный
BuildKit secret `build_ca`. Проверка TLS и целостности пакетов сохранена.

## Методология

Публичную страницу можно разместить до импорта матрицы; каталог честно
покажет отсутствие опубликованной версии. Для заполненных компетенций и
рабочего review по действующей методике нужен исходный XLSX со всеми
вкладками и формулами. Технические тестовые критерии публиковать нельзя.
